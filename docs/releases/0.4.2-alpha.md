# DashBridge 0.4.2-alpha

This prerelease corrects the USB setup page's false-green connection checks
when one board loses power or stops responding. The feature set and unresolved
car-side limitations of [0.4.1-alpha](0.4.1-alpha.md) remain unchanged.

## Changes

- Board A now accepts board-link heartbeats only from Board B, and Board B
  accepts them only from Board A. A reflected packet can no longer make an
  unplugged peer look connected.
- The setup page immediately withholds peer checks when a USB-connected board
  disappears. It waits for a new report after the peer's heartbeat timeout
  before trusting the other board as a proxy. Any silent USB status expires
  instead of remaining green indefinitely.
- A single USB data connection may still check a second board that is powered
  separately; both boards do not need a USB data connection for this view.
- The setup page now replaces the one-minute app-discovery message when the
  window ends, including if USB reports stop before the final update.

## Verification and limits

Host tests cover reflected heartbeats, the unplugged-board transition, stale
status, and a powered peer without its own USB data connection. Both ESP32
images build with the pinned ESP-IDF v5.5.5. Both matching applications were
installed at `0x10000` on the two development boards after their partition
tables were checked. Both booted, reported 0.4.2-alpha and a working wired
link; Board A still reported its saved iPhone Bluetooth and notification
connection. The power-loss transition has not yet been reproduced on hardware
with this release. The exact image hashes and hardware-validation flags are in
the [manifest](../../dist/manifest.json).

The setup screen reports protocol state, not proof that a notification appeared
on the Tesla or that call audio works. Tesla-side message, music, call-audio,
and phonebook behavior still require a parked-car test. Full-image installation
can erase pairings; a verified application-only update at `0x10000` preserves
the existing NVS partition.
