# DashBridge 0.4.3-alpha

This prerelease packages the current two-board firmware, web installer, and
iPhone companion setup flow together. It remains an experimental build, not a
verified daily-use adapter. The iPhone app is distributed through an internal
TestFlight group; it is not a public App Store download.

## What's new since 0.4.2-alpha

- Board A exposes a Bluetooth setup service for the companion app, reports its
  live connection state and saved app choices, and accepts app-choice changes.
  The iPhone-initiated notification connection and pairing/reconnection paths
  have been adjusted following physical-device testing.
- Board B's current image is rebuilt from the matching source. The web setup
  page remains available for USB diagnostics, pairing controls, and a Tesla
  test message; the iPhone app handles the simpler everyday app-choice flow.
- The companion app can defer the parked-car step, return to it later, show
  selected apps as individual rows, and time out discovery and connection
  checks. Its final confirmation asks whether a new notification actually
  appeared on the Tesla; Bluetooth status alone is not treated as proof.
- The installer publishes both matching, checksummed ESP32 images. Its full
  install replaces the board's flash contents and may erase saved Bluetooth
  pairings and app choices.

The [manifest](../../dist/manifest.json) records image sizes, source hashes,
flash addresses, and the pinned ESP-IDF revision. Install A and B from this
same release. For existing boards with the same partition layout, the separate
application-only binaries can be flashed at `0x10000` to preserve NVS; do not
flash an application-only binary at `0x0`.

## Verification and limits

Both images built with pinned ESP-IDF v5.5.5 and passed the host protocol and
SDK checks. The web installer validates their hashes and embedded versions.
The companion app's simulator navigation tests pass, but the simulator cannot
pair with the physical boards. These exact `0.4.3-alpha` images have **not**
been flashed and tested together with the iPhone and Tesla. The manifest keeps
`hardware_tested: false` for both. Previous board builds connected to the
iPhone, but notifications, clear bidirectional call audio, music playback,
phonebook/history sync, and reconnect behavior still need a parked-car test on
these release images. Earlier phonebook pulls returned zero records; do not
assume that is fixed.

Use the [setup guide](../SETUP.md) and the [parked-car checklist](../../README.md#parked-car-test-checklist).
Keep the existing direct-phone option until the bridge has been verified in
your own car.
